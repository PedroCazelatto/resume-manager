# Decisions

Project decisions that apply across features rather than to one task. Technical rules live in [`constitution.md`](constitution.md) and features in [`backlog/`](backlog/); a decision about one task stays in that task's file. Task files still repeat every decision they need, so a fresh agent can work from the constitution and the task file alone (constitution Art. X.5).

1. **No profile ID in URLs.** The selected profile is kept in an http-only cookie named `profile`, never in the URL path or query, so it maps onto a login session once the app has authentication. Application IDs (the folder name, e.g. `2026-11-09-globex-backend-engineer`) may appear in URLs, as in `/applications/<id>`, and are always resolved inside the cookie's profile (Art. III.7). Decided 2026-11-08 and 2026-11-09. See [profile-picker](backlog/profile-picker.md), [application-folders](backlog/application-folders.md).
2. **One run at a time.** A new run never starts beside a running one and is never refused: it waits in the queue. Decided 2026-11-15. See [run-queue](backlog/run-queue.md).
3. **Every way of sending a posting queues it.** Whatever sends a posting (the form, a list of links, the browser extension, the bookmarklet) puts it in the queue when a run is already working. Decided 2026-11-15. See [browser-extension](backlog/browser-extension.md), [indeed-postings](backlog/indeed-postings.md).
4. **`source` names the job platform.** In `job.md`, `source` is the platform the posting came from ("LinkedIn", "Indeed", otherwise the link's host name without `www.`), not how the text arrived (`url` or `paste`). Every posting has its link. Decided 2026-11-17. Constitution 10.0.0 amends the `job.md` row of Art. IV.5 for it (waiting for the user's review). See [job-posting-details](backlog/job-posting-details.md), [posting-by-url](backlog/posting-by-url.md), [browser-extension](backlog/browser-extension.md).
5. **Ended runs keep their progress.** A run that finished, failed or was cancelled keeps its steps and its context-size warning in the Runs list, as it left them, while it stays listed. Failed generations stay at their position in the list (2026-11-17). Decided 2026-11-16. See [run-progress](backlog/run-progress.md), [run-queue](backlog/run-queue.md), [context-size-warning](backlog/context-size-warning.md).
6. **The application page refreshes when its run ends,** however it ends, including a "Try again" or "Verify again" started from the page itself. Decided 2026-11-17. See [runs-list-changes](backlog/runs-list-changes.md), [reconnect-to-a-run](backlog/reconnect-to-a-run.md).
7. **Visual direction.** Clean and minimal, with the current shadcn/ui components; a vertical sidebar instead of a top header, holding the name, profile, runs and theme; a green accent. Decided 2026-11-15. On 2026-11-17: status badges keep their colours (running and finished green, failed red, needing text amber, others grey), the selected sidebar entry and the focus ring may use the green accent, and the home page becomes one table of applications with the queue in tabs. See [visual-pass](backlog/visual-pass.md), [home-applications-table](backlog/home-applications-table.md).
8. **The model never creates values.** A job's details (title, company, location, salary, work model, hours) are taken from the posting page's HTML whenever it holds them, and that value is always kept (Art. VI.2). Decided 2026-11-17. See [job-posting-details](backlog/job-posting-details.md).
9. **Removing, cancelling and deleting.** In the fetch queue, an X icon button removes a link: it is not fetched and nothing is saved. In the resume queue, an X cancels a waiting or running generation, which stays listed as cancelled and can be started again; a trash button deletes a run, only once it is cancelled, so no confirmation box is needed. Decided 2026-11-17. See [runs-list-changes](backlog/runs-list-changes.md).
10. **Icons come from Phosphor,** through one icon component of the app. Decided 2026-11-17. See [runs-list-changes](backlog/runs-list-changes.md).
11. **Pasting a posting is a last resort.** Links are the way to send postings; pasted text exists for postings the app can't read, and always carries its link. Decided 2026-11-17. See [link-handling-changes](backlog/link-handling-changes.md), [paste-posting](backlog/paste-posting.md).
