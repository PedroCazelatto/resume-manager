# Decisions

Project decisions that apply across features rather than to one task. Technical rules live in [`constitution.md`](constitution.md) and features in [`backlog/`](backlog/); a decision about one task stays in that task's file. Task files still repeat every decision they need, so a fresh agent can work from the constitution and the task file alone (constitution Art. X.5).

1. **No profile ID in URLs.** The selected profile is kept in an http-only cookie named `profile`, never in the URL path or query, so it maps onto a login session once the app has authentication. Application IDs (the folder name, a UUID since 2026-11-17) may appear in URLs, as in `/applications/<id>`, and are always resolved inside the cookie's profile (Art. III.7). Decided 2026-11-08 and 2026-11-09. See [profile-picker](backlog/profile-picker.md), [application-folders](backlog/application-folders.md).
2. **One run at a time.** A new run never starts beside a running one and is never refused: it waits in the queue. Decided 2026-11-15. See [run-queue](backlog/run-queue.md).
3. **Every way of sending a posting queues it.** Whatever sends a posting (the form, a list of links, the browser extension, the bookmarklet) puts it in the queue when a run is already working. Decided 2026-11-15. See [browser-extension](backlog/browser-extension.md), [indeed-postings](backlog/indeed-postings.md).
4. **`source` names the job platform.** In `job.md`, `source` is the platform the posting came from ("LinkedIn", "Indeed", otherwise the link's host name without `www.`), not how the text arrived (`url` or `paste`). Every posting has its link. Decided 2026-11-17. Constitution 10.0.0 amends the `job.md` row of Art. IV.5 for it (waiting for the user's review). See [job-posting-details](backlog/job-posting-details.md), [posting-by-url](backlog/posting-by-url.md), [browser-extension](backlog/browser-extension.md).
5. **Ended runs keep their progress.** A run that finished, failed or was cancelled keeps its steps and its context-size warning in the Runs list, as it left them, while it stays listed. Failed generations stay at their position in the list (2026-11-17). Decided 2026-11-16. See [run-progress](backlog/run-progress.md), [run-queue](backlog/run-queue.md), [context-size-warning](backlog/context-size-warning.md).
6. **The application page refreshes when its run ends,** however it ends, including a "Try again" or "Verify again" started from the page itself. Decided 2026-11-17. See [runs-list-changes](backlog/runs-list-changes.md), [reconnect-to-a-run](backlog/reconnect-to-a-run.md).
7. **Visual direction.** Clean and minimal, with the current shadcn/ui components; a vertical sidebar instead of a top header, holding the name, profile, runs and theme; a green accent. Decided 2026-11-15. On 2026-11-17: status badges keep their colours (running and finished green, failed red, needing text amber, others grey), the selected sidebar entry and the focus ring may use the green accent, and the home page becomes one table of applications with the queue in tabs. See [visual-pass](backlog/visual-pass.md), [home-applications-table](backlog/home-applications-table.md).
8. **The model never creates values.** A job's details (title, company, location, salary, work model, hours) are taken from the posting page's HTML whenever it holds them, and that value is always kept. A detail the page doesn't hold may be filled by the model only with what the posting's text states (Art. VI.2). Decided 2026-11-17. See [job-posting-details](backlog/job-posting-details.md).
9. **Removing, cancelling and archiving.** In the fetch queue, an X icon button removes a link: it is not fetched and nothing is saved. In the resume queue, an X cancels a waiting or running generation, which stays listed as cancelled and can be started again, with the posting edited or a note for the model. A failed row has no X. Instead of deleting, an archive button moves a cancelled run, a failed run or a finished application to the Archived tab of the home page, where it can be restored: an unfinished one goes back to Generating as cancelled, a finished one to Ready. An application keeps `archived_at` in its `job.md`. Nothing is deleted, so no confirmation box is needed. Decided 2026-11-17 and 2026-11-21. See [runs-list-changes](backlog/runs-list-changes.md), [home-applications-table](backlog/home-applications-table.md).
10. **Icons come from Phosphor,** through one file that is the only place importing them and lists the icons the app uses (`<Icon name="x" />`). `lucide-react` is removed. Decided 2026-11-17. See [runs-list-changes](backlog/runs-list-changes.md).
11. **Pasting a posting is a last resort.** Links are the way to send postings. There is no "Paste text" tab: the text is pasted only on a row whose fetch failed (Indeed included), and it always carries its link. Decided 2026-11-17. See [link-handling-changes](backlog/link-handling-changes.md), [paste-posting](backlog/paste-posting.md).
12. **Resumes are in English for now.** The language choice is removed, whatever the posting's language (Art. VIII.1). Decided 2026-11-17. See [english-only-resumes](backlog/english-only-resumes.md).
13. **Applications are named by a UUID,** so an application can exist before the model has read its title and company (Art. IV.3–4). Its folder and `job.md` are made when its link's fetch starts (an Indeed link: when it is added), so failed and cancelled rows survive a restart; old folders are renamed once. Decided 2026-11-17 and 2026-11-21. See [application-uuids](backlog/application-uuids.md).
14. **One application per link.** Adding a link again whose application failed or was cancelled starts that same application again, archived or not; a link whose application is waiting, running or finished is skipped. Decided 2026-11-17 and 2026-11-21. See [link-handling-changes](backlog/link-handling-changes.md), [application-uuids](backlog/application-uuids.md).
15. **Nothing restarts by itself.** Runs live in memory only (Art. IV.1). After a restart, an unfinished application is listed in Generating as cancelled, with "Try again". Decided 2026-11-21. See [home-applications-table](backlog/home-applications-table.md), [application-uuids](backlog/application-uuids.md).
16. **Ollama stays the inference server.** oMLX, LiteLLM and Inco AI were evaluated as alternatives and rejected. LiteLLM (a gateway to many hosted providers) and Inco AI (mostly hosted inference) conflict with Art. III.1–2, and LiteLLM would also bring Docker beyond the sandbox (Art. V.2). oMLX (an MLX server for Apple Silicon) was speed-tested with the app's own pipeline steps on the user's Mac (M4, 24 GB) with Qwen 3.5 27B at 4-bit. It gave no gain: both servers ran at about 6 tokens/s with the same prompt time, because both are limited by memory bandwidth. It also stopped 3 of 7 calls for memory pressure, even with its most permissive memory setting. On this hardware the model (`OLLAMA_MODEL`), not the server, sets the speed. Decided 2026-11-21.
