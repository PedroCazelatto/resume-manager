## What it does

- **"Waiting to fetch".** A link waiting for its turn in the fetch queue reads "waiting to fetch". Only the link being fetched, whose `fetch` step has begun, reads "fetching the posting". No new status: the label is derived from the run's steps.
- **Fetch queue: an X removes the link.** A row in the fetch queue (waiting to fetch, or fetching) has an X icon button, "Remove link". It takes the link off the fetch queue and off the list: the link is not fetched, a fetch in progress is stopped, and nothing is saved.
- **Resume queue: an X cancels the generation.** A run waiting for the model or running has an X icon button, "Cancel", in the Runs list and on the application page (next to "Waiting for another run to finish…", and next to the running step). A waiting run is cancelled at once and never starts; the running one stops as before ([cancel-a-run](cancel-a-run.md)). Either stays listed as "cancelled", with "Try again" when it has no application yet; one with an application links to its page, which has its own "Try again". The X replaced "Remove" on waiting runs and the "Cancel" button on the running one, and the page's "This run was removed from the queue." line is gone: a cancelled waiting run shows "This run was cancelled. The finished steps stay saved."
- **Failed rows have no X.** A run that failed (its fetch, or its generation) can't be cancelled: it has "Try again" (except an Indeed link's run) and the archive button.
- **An archive button instead of delete.** A cancelled run, a failed run (its fetch or its generation, Indeed links included) and a finished run have an archive icon button, "Archive". It takes the row out of the Runs list at once, without a confirmation box. Nothing is deleted.
  - A run with an application archives the application: `archived_at` (the time, an ISO timestamp like `fetched_at`) is written to its `job.md`, every other field and the body kept, so it stays archived after a restart. Every run of that application that ended leaves the list with it. A run without an application keeps the time in memory (`archivedAt`).
  - The button isn't offered, and the server refuses, while a run of the same application is still waiting or running.
  - Restoring removes `archived_at` (or the time in memory). The row comes back to the Runs list: a failed or cancelled run as "cancelled", with "Try again" when it has no application; a finished one as it was. A failed fetch comes back as "cancelled" and still offers "Paste the text" (and "Try again", except an Indeed link's run, which never gets one).
  - The archived list, with its "Restore" button, is a tab of the home page's table, built by [home-applications-table](home-applications-table.md). Until then an archived row just leaves the Runs list, and restoring is reachable through its routes only.
  - An archived run has no "Try again" and takes no pasted text until it is restored.
- **Icons.** Every icon in the app is a Phosphor icon (`@phosphor-icons/react`), through `src/components/icon.tsx`, the only file that imports from Phosphor: it lists the icons the app uses, by Phosphor's name in kebab-case, and components write `<Icon name="x" />`. An icon is hidden from screen readers; each icon button has its accessible name ("Remove link", "Cancel", "Archive"). `lucide-react` is removed. ESLint refuses an import of Phosphor or `lucide-react` anywhere else.
- **Pasting the text on every failed fetch.** Every row whose fetch failed, Indeed links included, offers "Paste the text". The form's "Paste text" tab opens with the link kept, and the text goes to that same run: the row keeps its ID, leaves the "needs the posting's text" state and joins the end of the resume queue. No new run takes its place, and `replaces` is gone. Pasted text still carries its link.
- **A failed fetch has its own notification:** "Couldn't read the posting: paste the text", with the link as the body. The tab title still starts with "Failed". Every other failure keeps its words.
- **The application page refreshes on any end.** A "Try again" or "Verify again" started from the application page refreshes the page when its run ends in any way (finished, failed, cancelled), like a run the page picked up after a reload.

## Where it lives

- `src/core/runs/queue.ts`:
  - `waitingToFetch` (item 1), `stopAction` (what a row's X does: `remove`, `cancel`, or none on an ended run), `removeLink` (replaces `removeWaiting`; the fetch queue only), `cancelRun` (now for a waiting run too);
  - `pasteText` (replaces `dropFetchFailed`: the same run, failed fetch or Indeed, moves to the end of the run queue with the pasted text; its error, `notFetched` and events are cleared);
  - `QueuedRun.archivedAt`, `ArchiveTarget` (an application, or a run without one), `archiveTarget`, `targetBusy`, `canArchive`, `archiveRuns`, `restoreRuns`; `runsOf` leaves archived runs out; `canTryAgain` is false for an archived run; `fetchFailed` is also true for a restored failed fetch, which is `cancelled`.
- `src/core/runs/notice.ts`: `EndedRun.fetchFailed` and `url`, `FETCH_FAILED_TITLE`; `runNotice` uses them for a failed fetch.
- `src/core/application/schemas.ts`: `jobSchema` has `archived_at`, an optional timestamp. `src/core/application/archive.ts` (new): `archivedJob` and `restoredJob` compute the new `job.md` (validated first, every other field and the body kept), or say it is invalid, already archived or not archived.
- `src/app/runs.ts`: `remove` cancels a waiting run (`"cancelled"`) and removes a link of the fetch queue; `enqueue` lost `replaces`; `paste`; `archiveTarget`, `restoreTarget`, `busy`, `archive`, `restore`; `RunSummary.archivable`.
- `src/app/run.ts`: `pasteRun`. `src/app/archive.ts` (new): `archiveRun`, `restoreRun`, `archiveApplication`, `restoreApplication`; `job.md` is read and replaced through `ProfileStore` (`readApplicationFile`, `replaceApplicationFile`, atomic), for the selected profile only.
- Routes and their answers:
  - `DELETE /api/runs/[runId]`: 204 for a link of the fetch queue (removed) and for a waiting run (cancelled), 202 for the running run (cancelling), 409 for an ended run, 404 for an unknown or another profile's run.
  - `POST /api/runs/[runId]/posting` (new): `{ posting, url }` for a run whose fetch failed or an Indeed link's run; 202 with the same `{ runId }`, 400 without the text or its link, 404 for an unknown or another profile's run, 409 for a run that doesn't need its text (or is archived).
  - `POST /api/runs/[runId]/archive` (new): 204; 404 for an unknown or another profile's run, or one whose application is gone; 409 for a run that hasn't ended, is archived already, or whose application has a run waiting or running, and for an invalid `job.md` (named with its path and problems).
  - `DELETE /api/runs/[runId]/archive` (new, restore): 204; 404 as above; 409 for a run that isn't archived, or an invalid `job.md`.
  - `POST /api/applications/[id]/archive` (new): archives an application by its ID, with or without a run in memory; 204; 404 for an unknown application or a name that isn't one; 409 when it is archived already, has a run waiting or running, or its `job.md` is invalid.
  - `DELETE /api/applications/[id]/archive` (new, restore): 204; 404 as above; 409 when it isn't archived or its `job.md` is invalid.
  - `POST /api/applications` no longer reads `replaces`.
- `src/components/icon.tsx` (new): `archive`, `caret-down`, `caret-up`, `check`, `list`, `moon`, `sun` and `x`, each imported from its own module of `@phosphor-icons/react/dist/ssr`. They replace lucide's `Archive` (new), `ChevronDown`, `ChevronUp`, `Check`, `Menu`, `Moon`, `Sun` and `X` in `src/components/ui/select.tsx`, `ui/dialog.tsx`, `ui/sheet.tsx`, `mobile-menu.tsx` and `theme-toggle.tsx`. `eslint.config.mjs` restricts the imports.
- `src/components/runs-list.tsx`: the "waiting to fetch" label, the X, the archive button, and the "cancelled" label of a restored failed fetch. `src/components/use-run.tsx`: `RunProgress`'s X (`cancellable` replaces `removable`), `removed` is gone from `Run`, and `start` resolves with true once its run has ended, however it ended. `src/components/retry-run.tsx`, `src/components/resume-editor.tsx`: refresh after any end. `src/components/new-application-form.tsx`: pasted text for a row goes to `POST /api/runs/[runId]/posting`.

## Rules it follows

- Art. IV.5, IV.7, IV.8 (`archived_at` in `job.md`, written atomically through `ProfileStore`, every other field and the body kept; nothing deleted, so no confirmation), IV.6 (an invalid `job.md` is named with its path and problems and left alone), IV.1 (a run without an application keeps its archived state in memory).
- Art. III.7 (runs and applications are archived, restored, cancelled and pasted on for the selected profile only), III.4 (the pasted posting is never listed, streamed or logged; the notification body is the user's own link), III.2 (an Indeed link is never requested, also after restoring).
- Art. V.3 (the statuses, transitions, the X, the archive rule, the `job.md` rewrite and the notification words are pure core code; the routes and components stay thin).
- Art. IX.2 (the model and the fetcher are mocked; no test opens a socket), IX.4 (`@phosphor-icons/react` approved by the user; `lucide-react` removed).
